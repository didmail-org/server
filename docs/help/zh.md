# DIDMail Server 帮助

为组织配置邮箱、管理节点，并了解邮件如何投递。本指南依据当前服务器和客户端编写；历史 VC 投递文档不代表可以启用一项受支持的功能。

<a id="overview"></a>

## 服务器的作用

DIDMail Server 保存加密邮件和附件。客户端在本地加密和解密内容；节点负责权限检查、存储、投递记录，以及必要的区块链交易。

系统中有三种不同身份：ARC 登录身份、邮件客户端中的邮箱 DID，以及服务器的节点钱包。登录管理站点不会自动把 ARC 账户变成邮箱，个人钱包也不是节点钱包。

同一服务器的成员互发邮件时，密文直接存储到节点：不要求信封、不付款、不创建邮件 NFT，也不发送链上通知。外部邮件继续使用 NFT 信封。服务器自动判断实际投递方式，用户不需要选择独立的发送模式。

“邮件数据不上链”指内部投递。账户此前的身份或质押交易仍可能存在于链上。存储、带宽等基础设施也仍由运营者承担成本。

<a id="quick-start"></a>

## 开始使用组织邮箱

1. 向运营者获取服务器 HTTPS endpoint 和加入该 ARC 组织的邀请。
2. 通过 ARC 邀请登录。组织身份必须是活跃的所有者、管理员或成员；访客或停用身份不具备成员邮件资格。
3. 在更新后的 DIDMail 扩展、React Native 或 Flutter 客户端中连接该 endpoint。创建或选择邮箱，完成客户端提供的 ARC 邮箱绑定流程；批准前核对显示的账户和服务器。
4. 让客户端登记加密接收密钥。仅完成绑定，不代表邮箱已能接收加密邮件。
5. 发送内部邮件前，发件人需要至少 1 个有效、未撤销的原生代币自质押。服务器只读检查，不为该邮件创建交易；等待领取的撤销金额不计入此项有效质押。
6. 请另一位成员在同一服务器完成连接、绑定和接收密钥登记。正常撰写邮件，确认前审阅实际内部邮件条款和保存期限。
7. 刷新收件箱。“内部邮件”和“外部邮件”是两个标签页；常规刷新也会同步内部邮件。保持客户端运行，直到正文和全部附件下载完成，再使用客户端备份功能。

启用成员投递的节点即使没有发布信封，也可以连接。向不满足内部条件的人发送邮件，需要可用的外部信封，并重新审阅实际条款。

<a id="access"></a>

## 登录并找到正确页面

打开 [DIDMail 管理界面](/admin)，由 ARC 验证会话和角色。帮助页公开可读；业务数据仅向所有者和管理员开放。普通成员通过邮件客户端使用邮箱，不通过管理控制台收发邮件。

- [节点账户](/admin/account)：节点 DID、余额、充值、所有者转出和免手续费质押。
- [服务节点](/admin/server)：服务节点 NFT、公开网络可见性及 NFT 质押。
- [成员](/admin/members)：ARC 成员状态、关联邮箱和被禁止的发件人。
- [信封](/admin/envelope)和[名片](/admin/namecard)：创建、发布模板。
- [存储](/admin/storage)：加密邮件记录、容量、搜索和删除。
- [设置](/admin/attachment)：附件政策和投递运行状态。

ARC 头像菜单也可能显示平台的 Admin Console。平台控制台与 DIDMail 业务管理用途不同：组织成员由平台组织工具管理，邮件运营由 DIDMail 页面管理。只有所有者能转出节点资金，或操作节点原生代币的免手续费质押、解除和领取。

<a id="node-account"></a>

## 管理节点钱包

在“节点账户”中，充值前先核对节点 DID 和网络。复制节点地址或扫描二维码，从自己的钱包发送对应网络的代币，随后刷新核对结果。余额不可用不等于已确认余额为零。

充值增加可用资金。免手续费质押按链规则锁定原生代币，不会支付信封价格或购买服务节点 NFT。成员发件人的 1 token 要求单独检查其个人发件钱包，不检查节点钱包。

所有者可以审阅向已授权的所有者地址转出可用资金的操作。已质押资金不能作为可用余额转出。进行免手续费质押时，审阅服务器显示的当前金额和解除等待期。解除质押会开始等待，不会立即退回代币；只有界面显示满足领取条件时才能领取。

交易结果不确定时，先刷新并检查原操作结果，再决定是否重试。升级或恢复已有服务器时保留原节点钱包：替换钱包会改变节点身份，并可能失去对原资产和加密域名密钥的访问。

<a id="server-node"></a>

## 私有 endpoint 与公开服务节点

私有组织可以直接分发 endpoint。内部成员投递不要求购买或质押服务节点 NFT，也不要求节点代付邮件 NFT。

如果希望出现在公开网络发现列表中，在“服务节点”检查已配置工厂、获取正确的节点 NFT 并管理其质押。公开可见性取决于有效的服务节点 NFT 质押，单纯有代币余额、原生代币免手续费质押或发送白名单都不能代替它。

保持公布的 endpoint 正确、可访问。批准购买、追加质押、解除或领取前，审阅网络、资产和当前链规则。公开可见性与发送权限是两个不同判断：公开节点仍可能拒绝无权限的发件人。

<a id="members"></a>

## 成员与邮箱绑定

“成员”页面显示来自已配置 ARC 成员源的信息，以及节点中的邮箱关联。组织调整后应刷新。成员源必须同时提供可信的活跃/停用状态和角色，仅有角色标签不够。

组织成员资格与邮箱绑定不同。没有绑定邮箱的 ARC 成员还不能使用内部邮件。客户端的“已绑定”标签只是显示缓存，不代表授权；服务器接受发送时会重新检查实时成员状态和绑定。

通过客户端提供的账户绑定或撤销流程关联正确邮箱。绑定不需要上传明文私钥。可选的加密恢复需要原恢复密码；节点不能解密备份或重置该密码。仅有助记词可能无法恢复随机生成的历史设备加密密钥，因此应保留客户端的完整加密备份。

在“被禁止的发件人”中维护发送限制和备注。对新发送，禁止规则优先于成员资格，不能靠付款绕过。成员变化或撤销不会改写已接受邮件的投递结果；删除本地“已绑定”标签也不会撤销服务器关联。

<a id="delivery"></a>

## 内部与外部投递

**内部邮件：**双方都必须是同一服务器的活跃、有效绑定且有资格的成员，收件人还必须有有效接收密钥。已选信封仅作为外部发送候选，不会用于内部邮件或产生费用。保存期限由节点内部政策决定。签名离线回执绑定消息、双方、服务器和保存期限；它不是链上证明，也不是已读回执。

**外部邮件：**已选且发布的 NFT 信封与当前签名报价决定收费和保存期限。零价成员信封可以使发件人付款为零，但节点仍可能付费铸造真实邮件 NFT。这与内部投递不同，仍会产生链上信息。发件人零价格不等于节点零成本。

如果内部报价生成后、正式接受前资格变化，发送会失败并要求刷新条款。服务器不会把免费授权静默转成付款或上链。成员源故障表示“无法验证”，不能解释为“非成员”。接受之后，重试返回原任务，不改变投递类型，也不再次收费。

“已投递”表示服务器完成了相应投递要求，不表示收件人已读或已完整下载。内部收件箱直接查询绑定服务器，不依赖 NFT 通知；原有外部邮件仍显示在外部收件箱。

<a id="envelopes"></a>

## 创建与发布信封

在“信封”创建模板、预览 SVG、设置价格和保存期限，并选择“公开”或“成员”分类。分类创建后固定；需要其他分类时创建新模板。成员分类限制的是哪些发件人可以使用，不要求每个外部收件人都加入组织。

创建或获取 NFT 前，审阅实际工厂费用。发布后模板才可通过本节点使用；取消发布会停止新选择。在可见且已发布的信封中，成员默认优先选择成员分类；同一分类内按本地最早记录确定默认项。客户端可选择其他可见信封。

零价成员信封可能由节点钱包承担外部邮件 NFT 的费用，因此该路径仍需节点有足够资金和免手续费资格。内部成员邮件完全绕过信封。现有 NFT 规则中信封保存期限为零表示无限期存储，不能用它覆盖独立且有限的内部邮件保存政策。

<a id="namecards"></a>

## 创建与发布名片

在“名片”预览 SVG、配置现有价格和保存期限、选择公开或成员分类，然后创建并发布。使用提供的模板示例，保留必需的 `{{contact.name}}` 占位符。信封 SVG 与名片 SVG 使用不同的渲染字段。

分类控制谁能使用模板，创建后不能修改。发布不代表已发送名片。联系人/名片交换有独立的交易和付款规则；内部邮件免费不代表名片交换自动免费或离线。如果已付款操作停滞，保留原准备单和交易标识，不要再次授权重复付款。

<a id="storage"></a>

## 存储、下载与备份

在“存储”搜索、翻页查看节点邮件记录，检查状态和容量，操作后刷新。服务器保存加密正文、附件及运行元数据；管理页不是可阅读邮件明文的收件箱。

删除服务器记录会移除可用的服务器内容。操作前核对对象和保留需要。删除不能撤回客户端已下载副本，也不能抹去已有链记录。不要通过删除邮件来“修复”结果仍不确定的付款或投递。

客户端把已下载内容保存在本地。正文可读不代表全部附件已存在：未完成附件仍处于待下载状态，可以重试；单封失败不应阻塞其他邮件同步。使用客户端完整加密备份，并保留必要的历史解密密钥。本指南不承诺自动迁移服务器，也不承诺节点保存期结束后恢复未备份的内容。

节点备份需要原节点钱包、关系数据和相匹配的加密对象。只有 D1 导出不构成完整 D1/R2 备份。跨存储一致快照需要先暂停写入，所有私有导出都应放在公开应用包之外。

<a id="settings"></a>

## 配额与保存期限

在“设置”配置现有附件控制，并查看投递运行状态。附件数量、单文件大小、附件总大小与整封密文限制同时生效，填写前核对各字段单位。超限草稿被拒绝后，先修改内容再重新提交。

内部邮件不设每日封数、累计存储容量或待上传任务数量配额，也不占用外部邮件的未付款上传名额。保存期限通过部署配置设置，默认 30 天，不是“成员”页面中的额外表单。单封邮件与附件大小限制、请求频率限制和上传有效期仍然生效。运营者监控实际基础设施容量。

运营者使用以下准确配置名：

```text
DMP_INTERNAL_RETENTION_DAYS=30
```

修改不追溯改变已接受的条款。如果编辑过程中政策变化，先刷新并审阅后再保存。已退役的普通/链上 VC 投递不是可以重新开启的受支持设置。

<a id="troubleshooting"></a>

## 常见问题

- **无法打开管理界面：**通过 ARC 登录，核对本实例是否识别为所有者或管理员。ARC 连接不可用时应修复连接，自报角色或 DID 不能代替身份验证。
- **显示已绑定，但内部发送失败：**检查双方当前成员状态、未撤销绑定、接收密钥及发件人有效原生代币自质押。核对禁止规则，并确认客户端版本兼容、使用同一服务器。
- **`MEMBERSHIP_UNAVAILABLE` 或 `GAS_STAKE_UNAVAILABLE`：**服务器无法验证来源，运营者恢复服务后重试；错误不代表没有成员资格或质押为零。
- **`DELIVERY_TERMS_CHANGED` 或政策冲突：**保留草稿，刷新条款并审阅新结果，不要把原付款授权用于变化后的投递。
- **`ENVELOPE_REQUIRED`：**收件人不满足内部条件。选择可用外部信封并审阅费用；如果没有已发布信封，联系运营者。
- **单封邮件或附件大小超限：**缩小草稿后再重试。外部邮件达到未付款上传数量限制时，先完成现有外部上传或等待其过期。不要为同一次失败发送反复创建新上传任务。
- **已接受、处理中或结果不明：**刷新原任务，保留消息 ID，以及存在时的原交易哈希。投递运行状态可能显示需人工对账的任务，不能仅因响应超时就再次付款。
- **正文已下载，附件缺失：**在节点仍保留附件时重试，检查本地空间和连接。缺少历史解密私钥时需要原设备密钥备份，再查 NFT 不能解决。

联系运营者时提供客户端版本、endpoint、消息 ID、错误码和发生时间。不要发送私钥、助记词、恢复密码、会话 Cookie 或未脱敏邮件内容。

<a id="deployment"></a>

## 运营者部署与升级

当前服务器使用 Cloudflare Workers、保存关系数据的 D1 和保存加密对象的 R2。ARC 经已配置的可信集成提供登录和权威组织成员信息。HTTPS 私有 endpoint 本身不代表已实现物理隔离或企业内网部署。

1. 配置公开 HTTPS origin、目标网络、专用 D1/R2 资源和可信 ARC 连接。节点钱包密钥放在私有配置中，并核对公开节点地址。
2. 提供成员邮件前，配置限定实例的成员适配器和账户绑定能力。保护凭据，过期前轮换；不能用仅包含角色的列表替代已验证活跃状态。
3. 先构建协议 SDK，再构建链接使用它的组件。使用服务器配置的 pnpm 版本安装依赖并构建服务器，按序应用所有待执行 D1 迁移；成员直接存储需要 `0016_member_mail.sql`。
4. 保留原节点身份和数据。在隔离环境测试，再验收登录、成员、接收密钥、内部同步及计划提供的外部投递路径。
5. 分发正确 endpoint 和兼容客户端，保持定时投递恢复与到期清理运行，监控容量和需对账的任务。

在本仓库开发时使用 Node.js 24.14 或更新版本，从 `server/` 执行：

```sh
pnpm install --frozen-lockfile
pnpm arc:run
```

本地规定使用 ARC 实例 `didmail-web`，通过 `http://didmail-arc.localhost:8788` 访问。`pnpm start` 是独立的 Workers-only 入口，端口 8787。需要时只停止受影响的业务预览，保留其 D1/R2 状态，不干扰其他 ARC 实例。本地构建或部署 dry run 不代表已完成远端生产部署。
